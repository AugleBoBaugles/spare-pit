# Spare Pit Deployment Guide

There is also an [online version of this guide](https://docs.google.com/document/d/1L76iXOH6ml9GdBn7CURlDEe_7l-3rIdocH12cPhhZ44/edit?usp=sharing), including screenshots.

Spare Pit is an inventory app built by Green River College students Augy Markham and Rebecca Riffle.

This guide will walk you through hosting the Spare Pit App for your team. Here's a quick summary of the steps you will take:

1. Create your own copy of the code on GitHub.
2. Make a database to hold your data that lives on the internet.
3. Launch a web service to serve that data out to your app, accept incoming data, and make sure it knows how to talk to your database and website.
4. Make a website that gets data from the web service.
5. Send an email (don't worry - we wrote it for you!) to your school district IT team, asking them for permission to access your site on the school wifi.
6. Keep your site live by visiting it at least once a month.

## Fork the Repository

Create a copy of the code base that you can use and customize for your team.

1. Go to https://github.com/AugleBoBaugles/spare-pit
2. Select **Fork**.
3. In **Repository name**, enter `[Team Name]-spare-pit`. (Ex. `lucky-spare-pit`)
4. (Optional) In **Description**, add a short description. (Ex. "Green River HS Lucky Robotics Team Inventory Tracker".)
5. Select **Create fork**.
6. Save the <mark>**forked repo URL**</mark> in your notes. (ex. `https://github.com/user/sample-spare-pit`)

## Deploy Database on Supabase

Host the database online so you can share data online.

### Create an Account

1. Go to https://supabase.com/
2. Select **Sign in**.
3. Select **Continue with GitHub**.
4. If prompted, select **Authorize Supabase** to allow Supabase to connect to your GitHub.

### Create an Organization

1. Select **New organization**.
2. Enter Organization details:
   - **Organization name** → <mark>**[Team Name]**</mark> Spare Pit
   - **Type** → Educational
   - **Plan** → Free - $0/month
3. Select **Create organization**.

### Create a Project

1. Select **Create a new project**.
2. Enter Project details:
   - **Organization** → <mark>**[Team Name]**</mark> Spare Pit
   - **Project Name** → <mark>**[Team Name]**</mark> Spare Pit DB
   - **Password** → Select **Generate a password**, then click **Copy**
3. Record the <mark>**Supabase password**</mark> in your notes. You will need it in a few steps.
4. Select **Create new project**.

### Create Inventory Table

1. Select **SQL Editor**.
2. Enter (Copy + Paste) this code into the text editor to write the inventory table:

```sql
create table inventory (
  id            bigint generated by default as identity primary key,
  name          text        not null,
  type          text,
  area          text,
  location      text,
  status        text,
  quantity      integer,
  condition     text,
  "itemImage"   text,
  "checkOutBy"  text,
  "lastUpdated"   timestamptz default now(),
  tags            text,
  notes           text,
  "needsRestock"  integer     default 0
);
```

3. Select **Run** > **Run without RLS**.

> **Note:** If you run into the following error, wait a couple of minutes and try again.
> ```
> Failed to run sql query: ERROR:  25006: cannot execute CREATE TABLE in a read-only transaction.
> ```

### Get Connection String

1. Select **Connect**.
2. Select **Direct Connection string**.
3. Select the **Transaction Pooler** Connection Method.
4. Copy the connection string and replace `[YOUR-PASSWORD]` with your <mark>**Supabase password**</mark>. Record the updated URL as your <mark>**Supabase connection string URL**</mark>.

You have set up the database! You will not need to return to Supabase for the rest of this deployment process.

## Deploy API on Render

The API helps data travel safely between the front end and the database, handling errors and data cleaning.

### Create Render Account

1. Go to https://render.com/
2. Select **Start for free**.
3. Select **GitHub** to create an account using your GitHub credentials.

### Create Web Service

1. Select **New** > **Web Service**.
2. Select **GitHub** to set Git Provider.
3. Select **Only Selected repositories** > `[Team Name-name-spare-pit]`
4. Allow **Read** permissions.

### Configure Web Service

Enter the following configuration details:

| Field | Value |
|-------|-------|
| Name | `[your-team-name]-spare-pit` |
| Root Directory | `server` |
| Build Command | `npm install` |
| Start Command | `npm start` |

Select **Free $0/month 512 MB (RAM) 0.1 CPU**.

### Add Environmental Variables

Enter the following environmental variable:

| Key | Value |
|-----|-------|
| `DATABASE_URL` | `[Supabase connection string URL]` |

This tells your server where the database lives. We will return to this section later to add more variables!

Select **Deploy web service**.

> **Note:** It will take 1-3 minutes to deploy the first time you run this.

Record your **Render Server URL**.

### Confirm Success

1. Go to your Render Server URL. (Replace the URL in the example below with your URL)

If you have successfully deployed your API web service, you should see:

If you do not see this message, then there's an issue with your server.

If you see a server error, there is an issue with your database connection.

## Deploy Frontend

The frontend is the graphical interface, where the user can "see" and update the database.

### Create Account

1. Go to https://app.netlify.com/
2. Select **Log in with GitHub**.
3. Select **Add new project**.

### Connect Project to GitHub

1. Select **Import from GitHub**.
2. Select **Configure the Netlify app on GitHub**.
3. Confirm your account.
4. (If needed) Select **Verify via Email**.
5. Select **Only select repositories** > **Select repositories** > `[Team Name]-spare-pit`
6. Select **Save**.

### Configure Frontend

1. Select your project.
2. Enter the following configuration details:

| Field | Value |
|-------|-------|
| Project Name | `[your-team-name]-spare-pit` |
| Base directory | `client` |
| Build Command | `npm install && npm run build` |
| Publish directory | `dist` |

3. Add the following Environmental Variable:

| Key | Value |
|-----|-------|
| `VITE_API_BASE` | `[Render Service URL]` |

4. Select **Deploy [your-app-name]**.

> **Note:** This will take a minute or two to deploy.

5. Record the **Netlify frontend URL**.

### Confirm Success

Go to the URL to see a basic interface. There will be an error warning that it couldn't find the data because we have a few more configurations to update.

### Connect Server and Frontend

1. Go to https://dashboard.render.com/
2. Select `[your project name]`.
3. Select **Environment**.
4. Add the following environmental variable:

| Key | Value |
|-----|-------|
| `CORS_ORIGIN` | `[Netlify Frontend URL]` |

This will allow the API and the frontend to connect.

5. Save, rebuild, and deploy.

### Confirm Success

1. Visit your frontend URL.
2. Select **Add Item**.
3. Enter all the required fields, select **Add Item**.
4. Select **Inventory**.

If the item shows up in the main inventory view, everything is working as it should! Do a happy dance.

If not, check out the Maintenance table for Netlify troubleshooting.

## Maintenance

Let's make sure you understand how this app works so you can maintain it appropriately. The best thing you can do is visit your app at least once a day to keep it active. Delete any unexpected content that shows up. If you start getting a lot of bad content, consider redeploying (make a new Supabase DB, Render Web Service API, and Netlify frontend).

Here are some technical details about each of the hosting services, for reference and troubleshooting:

| | Netlify frontend | Render backend | Supabase DB |
|---|---|---|---|
| **Cost** | Free tier | Free tier | Free tier |
| **Available Resources** | ~150 credits to deploy and test. 150–250 credits per month to maintain. | 750 free instance hours per calendar month (enough for one service running 24/7). | 500 MB of storage. |
| **Limitations** | 300 credits per month. | Services spin down after 15 minutes of inactivity, resulting in 30–60 second cold starts when traffic resumes. | Pause after 1 week of inactivity, resulting in 1–2 minute spin-up time. Full deletion after 90 days of inactivity. |
| **Troubleshooting** | [Netlify docs](https://docs.netlify.com/resources/troubleshooting/overview/) | [Render docs](https://render.com/docs/troubleshooting-deploys) | [Supabase docs](https://supabase.com/docs/guides/troubleshooting) |

For more information about how each part works, check out the project README.
